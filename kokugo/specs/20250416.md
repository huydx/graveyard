## Requirement

- A new feature to help the kid to learn about his interested topic
- Basically the kid have weekly digest which can be a length of 500 to 1000 words so he can read and understand
- The digest have challenge enough keywords and nuances that can help he learn something new
- There is a single topic at a time
- The kid can change the topic any time
- Changing the topic only change future digest
- There should be at least 1 stock. If when open the page and there is no stock, generate one (the UI should be aware of this)
- Everytime a kid finish a stocked digest it will automatically generate new digest to fit stock in background
- Each stock has a 'sub topic' which should not be duplicated with existing one
- Store sub topic in the database so we can make sure there is no duplication

## UX

- That new feature should separate from the existing print feature, but still under kokugo
- If we don't have topic yet, start with topic insert screen
- Kid can change topic
- If we have no stock yet, have a button to generate stock

### UX detail (frontend side)

- Add a dedicated page under kokugo: `/kokugo/digests`
- Sidebar should show a separate nav item for weekly digest (not mixed into print list)
- First state (no topic):
  - Show single topic input + save button
  - After save, stay on digest page and fetch stock
- Normal state (topic exists):
  - Show current topic, edit mode, and "change topic" action
  - Changing topic updates only future stocks (existing old-topic items are not shown)
- Stock state:
  - Show stocked digest cards with sub-topic + preview text
  - Open one digest to read full content
  - "Done" action marks digest complete, then refreshes list
- Empty stock state:
  - Show explicit "Generate stock" button
  - Button triggers backend refill and then reloads stock list
- Keep UI kid-friendly:
  - Simple wording
  - Large tap targets
  - One primary action per state
